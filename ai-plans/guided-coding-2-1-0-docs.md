# Document Guided Coding 2.1.0

## Rationale

Guided Coding 2.1.0 (`~/Code/guided-coding`, tag `2.1.0`) adds `guided-coding-plan-and-review`, the RDAT plan structure, premise checks with bounded workarounds in the implement skills, and Plan Deviations documents that stay editable until merged. The docs in `docs/guided-coding/` describe 2.0.0 and now contain wrong statements about the skills.

## Decisions

- **D1 – Page structure.** Add three pages: `plan-structures.md` (Plan Structures), `automated-plan-review.mdx` (Automated Plan Review), and `release-notes.md` (Release Notes). Sidebar order: Overview, Guided Coding: Getting Started, Guided Learning: Getting Started, Planning Phase, Implementing Phase, Guiding Phase, The Plan Record, Plan Structures, Automated Plan Review, What Belongs in a Rules File, Finding the Right Plan Size, Security, Communication, Comparison, Release Notes. Reason: details that several pages refer to get one home, and Getting Started stays a walkthrough.
- **D2 – Version history.** "What Changed in Version 2.0.0" leaves `index.mdx`. The overview links to Release Notes in one sentence. Release Notes has a 2.1.0 and a 2.0.0 section and links to the CHANGELOG on GitHub. Reason: the overview should not grow with every release.
- **D3 – Plan structures.** Plan Structures explains the default structure, RDAT (why Decisions exist, Decision IDs, the Out-of-Scope Decision, checking assumptions against the code, each section adding information), the optional `## Notes for the Guided Learning Teacher` section, and how to pick a structure per plan, per repository, or bring your own. The method text in Planning Phase keeps Rationale, Acceptance Criteria, and Technical Details as the minimum and links to Plan Structures. The Opinionated Path uses RDAT.
- **D4 – Plan and review in the method.** Planning Phase "Reviewing the Plan" adds the method-level idea: independent reviewers in fresh contexts can review a draft in rounds before you read it, and this never replaces your own review. The docs say explicitly that `guided-coding-plan-and-review` runs after the discussion, in the same conversation, never changes your explicit decisions without asking, and ends where your review begins.
- **D5 – Plan and review in Getting Started.** Steps 2–5 offer two paths: the existing manual loop, or `guided-coding-plan-and-review` in step 2 followed by reading its report (findings and the list of decision and scope changes) before the further discussion. Configuration, finding classes, `collect`/`pause`, models per reviewer, cost (reviewers × rounds, plus replacements), and how to read the report live on Automated Plan Review.
- **D6 – Timeline.** `GuidedCodingSkillTimeline` gets an optional `variant` prop (`'manual'` default, `'plan-and-review'`). The `plan-and-review` variant replaces the write/review steps of the Planning card with `guided-coding-plan-and-review` and a manual "Read the report and the plan" step. Getting Started shows both variants in Tabs. `GuidedLearningSkillTimeline` stays unchanged.
- **D7 – Plan issues during implementation.** Implementing Phase replaces "stop and go back to the Planning Phase" with a section on wrong plans: check the plan's premises against the code before coding, the four conditions under which a workaround is allowed, criteria met only through a workaround stay unchecked, and otherwise stop only the affected work and report it. Getting Started step 7 matches.
- **D8 – Guiding Phase duties.** Guiding Phase adds: judge each reported workaround (accept and check off the criterion, or reject and write a Follow-Up Plan), and re-run `guided-coding-write-deviations` when PR review leads to another Follow-Up Plan.
- **D9 – Plan Deviations lifecycle.** The Plan Record and every other page state the 2.1.0 rule: one Plan Deviations document per work item, renamed with a new timestamp on each update so it sorts after all plans, frozen once merged into the target branch. To redo a merged one, delete it and run the skill again. "Frozen once committed" disappears everywhere.
- **D10 – Root `AGENTS.md` guidance.** The docs recommend what `guided-coding-setup` creates: frozen-plan rules in `ai-plans/AGENTS.md`, and a `## Guided Coding` section in the root `AGENTS.md` that only links to it. This replaces the "When you implement a plan" snippets in `implementing-phase.mdx` and `rules-files.md` and corrects the description of setup in Getting Started step 0 and the Rules Files callout.
- **D11 – Skill facts.** Correct skill counts (seven Guided Coding skills plus two Guided Learning skills, nine in total), including `security.md`. Replace "All skills are manually invoked" with: `guided-coding-write-plan` and `guided-coding-review-plan` can be invoked by the model so other Guided Coding skills can use them, but only at the request of the user or another Guided Coding skill. Security mentions that `guided-coding-plan-and-review` starts subagents that run with your permissions. Getting Started step 0 customization tips match the 2.1.0 setup skill (plan structure incl. RDAT, plan review config).
- **D12 – Guided Learning.** Guided Learning: Getting Started describes the premise check, temporary tests or projects that the agent removes again ("the agent makes no lasting changes" replaces "never changes your repository"), workarounds discussed with you before they go into the code, pausing and asking you when no workaround is allowed, the summary for the reviewer, and the teacher-notes section of RDAT.
- **D13 – Rules files.** What Belongs in a Rules File uses the plan structure choice and the `## Plan Review` section as examples of guidance that belongs in `ai-plans/AGENTS.md`.
- **D14 – Out of scope.** A 2.1.0 blog post, changes to the 2.0 blog post, `GuidedLearningSkillTimeline`, and the README of the guided-coding repository.

## Technical Details

- **Source of truth for skill behavior:** the skills in `.claude/skills/` (installed from tag `2.1.0`), plus `README.md` and `CHANGELOG.md` in `~/Code/guided-coding`. `guided-coding-plan-and-review/SKILL.md` and `guided-coding-write-plan/assets/rdat-plan-structure.md` are the main references for D3–D5.
- **Two layers:** method text is tool-independent; skill names and exact prompts go into `:::tip[The Opinionated Path]` callouts (see `index.mdx`). Follow this for D4, D7, and D8. Voice: explain the reason for a rule where the reader needs it, don't lecture.
- **Sidebar:** autogenerated from `sidebar_position` frontmatter (`sidebars.ts`). D1 requires renumbering every page after The Plan Record.
- **Skill invocations:** every invocation uses the `<Tabs groupId="guided-coding-install">` pattern with Agent Skills and Claude Code plugin tabs, so pages that show invocations must be `.mdx`. Plan Structures needs no invocation Tabs if it names skills inline only.
- **Links:** use relative Markdown links (`./plan-structures.md`). Never hardcode `/docs/...` hrefs in components, see the preview note in the root `AGENTS.md`. No inbound links to the removed `#what-changed-in-version-200` anchor exist.
- **Timeline (D6):** `src/components/GuidedCodingSkillTimeline/index.tsx` builds the SVG from a `cards` array; `loop: {from, to}` indexes steps within a card, and the accessible description string must change with the variant. Keep the default export's output identical when no prop is passed. Use a separate Tabs `groupId` for the variants so they don't sync with the install Tabs.
- **Configuration example (D5):** show a `## Plan Review` section with two reviewers on different models, `Round limit: 3`, and `User decisions: collect`, and note that model names are harness-specific.
